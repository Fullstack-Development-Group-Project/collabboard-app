# CollabBoard

A collaborative Kanban-style task board where a small team can create boards, add tasks, move tasks between columns, and see teammates' changes update live.

## Tech Stack
- **Frontend:** React, Vite, CSS
- **Backend:** Node.js, Express (WIP)
- **Database:** MongoDB via Mongoose (WIP)

## Architecture & Design

### React Component Tree
Our static UI follows this clean, reusable hierarchical structure:
```text
App
 ├── Navbar
 └── Board
      └── Column (Reusable for To Do, Doing, Done)
           └── TaskCard (Reusable for individual tasks)
```

## Local Setup Instructions

1. **Clone the repository:**
   ```bash
   git clone https://github.com/Fullstack-Development-Group-Project/collabboard-app.git
   cd collabboard-app
   ```
2. **Install dependencies:**
   ```bash
   npm install
   ```
3. **Run the local development server:**
   ```bash
   npm run dev
   ```
4. Open `http://localhost:5173` in your browser.

## Developer Guidelines

### 1. Required Application Versions
Please ensure your local environment matches these exact major/minor versions. Standardizing this prevents "it works on my machine" bugs.
- **Node.js:** v26.x (Install the current stable release, such as v26.2.x)
- **React:** v19.2.x
- **Express.js:** v5.x
- **Mongoose:** v9.8.x
- **Socket.io:** v4.8.x

### 2. Package Manager
We are exclusively using `npm` for this project. Do not use yarn or pnpm to install dependencies, as mixing package managers will cause lockfile conflicts and break our CI pipeline.
**Action:** Run `npm install` immediately after cloning the repository.

### 3. Formatting & Code Quality
Since 15% of our grade is based on Architecture & Code Quality, consistent style is mandatory.
- Please install the **Prettier** and **ESLint** extensions in your code editor (VS Code is highly recommended).
- Ensure your editor is configured to `"Format on Save"` so all code pushed to the repository is uniformly styled and passes peer review easily.

### 4. GitHub Issue Creation
Before writing any code, there must be a tracking issue for the task. This helps our subgroups stay organized.
1. Navigate to the **Issues** tab in our GitHub repository and click **New Issue**.
2. Give it a clear title (e.g., "Build TaskCard Component") and a brief description of the required work.
3. **Assign the issue to yourself** so the team knows exactly who is handling what.
4. Note the *Issue number* generated by GitHub, as you will need it for your branch name.

### 5. Branch Naming Convention
Direct commits to main are locked. All work must happen on feature branches and be submitted via Pull Request. When creating your branch, use the following structure:
`<type>/<issue-id>-<short-description>`

**Allowed Types:**
- `feature/` : For new features or UI components.
- `bugfix/` : For fixing broken code.
- `refactor/` : For code improvements that do not change functionality.
- `test/` : For adding or updating automated tests.
- `docs/` : For documentation updates.

*Example: If you are working on Issue #4 to build the task card layout, your branch should be named: `feature/4-task-card-ui`*
